# GRUNVALDLAB — Code Animation Director (v1.0)

## Выбор среды исполнения — политика GRUNVALDLAB

**Основной путь: Codex Cloud**, на изолированном облачном окружении OpenAI с привязанным репозиторием, Node.js 22+, FFmpeg и Chromium. Не отправлять монтаж и рендер в GitHub Codespaces по умолчанию: владелец намеренно избегает его ограниченных квот. GitHub Actions также не использовать для фонового рендера.

**ChatGPT Work** использовать для сценариев, анализа референсов, работы с файлами и оркестрации. Его cloud browser сам по себе не гарантирует терминал и пригодность для полного цикла локального HyperFrames; сначала проверять реальные инструменты окружения. Если доступен исполняемый код и FFmpeg, допустимо рендерить непосредственно в ChatGPT и отдавать MP4 как файл без внешних сервисов.

**Обычный ChatGPT** также может использовать доступные контейнерные инструменты для HTML/JS → кадров → FFmpeg без HyperFrames. В этой среде 12 октября 2026 подтвержден технический тест 2с/24fps/H.264. Полный HyperFrames не проверен: npm registry недоступен из этого сеанса. Не переносить факт успеха этого окружения на все Work/Codex окружения без проверки.

**Codex Cloud первичная настройка**: выбрать grunvald91/video-use, создать и опубликовать облачное окружение, задать setup для Node 22+, FFmpeg и browser/Chromium, проверить сеть к npm, запустить `npx hyperframes doctor`. Только затем выполнить короткую 5–10с пробу с аудио и MP4. Работать в той же задаче, сохранять нужные исходники и результат, не полагаться на бессрочную сохранность непрокоммиченных файлов.

**Хранение**: исходники — репозиторий и/или прикрепленные файлы, готовый видеофайл — скачиваемый артефакт задачи или выбранное хранилище. Большие MP4 не коммитить автоматически в Git. Если HyperFrames недоступен, использовать проверенный офлайн путь (HTML/JS + Playwright/Chromium + FFmpeg) при наличии этих инструментов.

Официальное подтверждение: https://help.openai.com/en/articles/20001545-using-codex-cloud ; https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt .

## Когда применять

Когда просят: «создай моушн-ролик», «заанимируй объяснение», «сделай мультфильм кодом», «создай анимированную демонстрацию продукта», «сделай ролик для ServGo», «анимируй инфографику». Применять как самостоятельную производственную инструкцию.

Если передан исходный разговорный ролик и задача — убрать паузы/оговорки, **сначала** прочитать корневой SKILL.md репозитория video-use и работать по исходному звуку; данный скилл использовать для графических вставок, а не вместо монтажа. Не заменять реальные кадры выдуманными и не выдавать генерацию за документалистику.

## Что должно получиться

Главный артефакт — смонтированный, проверенный MP4. Также сохранить редактируемый исходный HTML/JS, локальные медиа, раскадровку, файл стиля и отчет QA. Не выдавать одно описание вместо готового результата, когда рендер доступен. Если среда не позволяет собрать видео, назвать точную причину; не обещать фоновую работу.

## Автономный рабочий процесс

1. **Понять задачу:** аудитория, одна ключевая мысль, проверяемые факты, желаемое действие зрителя, платформа и длительность. Достаточные исходные условия брать из беседы и файла. Не спрашивать разрешения на каждое творческое решение.
2. **Сюжет:** сформулировать обещание для первых 1–3 секунд; выстроить «проблема → демонстрация → решение → вывод/CTA» либо более уместную драматургию. Каждая сцена объясняет одну мысль. Никогда не начинать с обрезанного слова или случайного куска.
3. **ДНК стиля:** создать/обновить DESIGN.md по references/STYLE_DNA.md. Зафиксировать цвета, типографику, пропорции, тип движения, света, фактуры и переходов. Одна семья решений на ролик; менять стиль только по сюжетной причине.
4. **Референсы:** разбирать доступные законно полученные примеры по сценам: композиция, траектория, амплитуда, длительность, ритм, свет, движение камеры. Не утверждать, что видео просмотрено, если доступны лишь описание/субтитры. Не копировать защищенные кадры и музыку.
5. **Раскадровка:** составить BEATS.md — таймкоды, текст диктора, титры, визуальная метафора, объекты, движение и звук. Для двухминутных+ роликов разделить на небольшие сцены и потом объединить.
6. **Код:** по умолчанию HyperFrames + HTML/CSS/SVG + GSAP с детерминированной перемоткой. Для объемной сцены обоснованно выбрать Three.js/Blender, для готовой анимации Lottie, для сложного видео — другой движок. Не усложнять 3D там, где хватает 2D.
7. **Рендер:** сначала короткий технический тест, затем выборочные стоп-кадры, затем превью, затем итоговый MP4. Тяжелый GPU-сервер не нужен по умолчанию; если требуется, оценить стоимость перед запуском.
8. **Самокритика:** до показа результата проверить первый/последний кадры, границы каждой сцены и несколько промежуточных кадров, текст, орфографию, читаемость, синхронизацию голоса, отсутствие скачков звука, битые изображения, обрезанные слова, визуальную связность. Найденную проблему исправлять и проверять заново.
9. **Память ошибок:** каждую повторяющуюся проблему и её исправление записывать в локальный MISTAKES.md проекта; перед следующим роликом читать его. Начальный перечень есть в references/MISTAKES.md.
10. **Публикуемый результат:** edit/final.mp4 + edit/source/ + edit/BEATS.md + edit/DESIGN.md + edit/QA.md + edit/MISTAKES.md. Публикация на внешние площадки — только по отдельному поручению.

Если стиль видеостудии еще не утвержден, по возможности создавать два законченных демонстрационных клипа по 20–30 секунд на одном содержании: A — динамичный YouTube, B — премиальный кинематографичный. Не создавать «разорванную» нарезку ради динамики.

## HyperFrames: технический контракт

- Официальный upstream: https://github.com/heygen-com/hyperframes ; документация: https://hyperframes.app/docs/1-startup/2-quickstart .
- Требования: Node.js 22+, FFmpeg; браузер/Chromium для локального рендера по требованиям выбранной версии. Перед командой проверять версии и наличие интернета.
- Для Claude Code: официальный плагин из heygen-com/hyperframes либо standalone-набор через npx. Для Codex/других агентов: отдельные HyperFrames skills. Использовать их **в дополнение** к настоящему режиссерскому скиллу.
- Типовой рабочий цикл: «npx hyperframes init <имя-проекта>», редактирование index.html, «npx hyperframes lint», «npx hyperframes check», «npx hyperframes preview», «npx hyperframes render --output edit/final.mp4». Перед использованием проверять синтаксис команд у установленной версии.
- В HTML у корневой композиции должны быть data-composition-id, data-width, data-height; у timed clip — class="clip", data-start, data-duration, data-track-index. GSAP timeline создавать paused и регистрировать в window.__timelines. Не использовать недетерминированные анимации без управляемой перемотки.
- Хранить исходники и лицензии медиа локально; не строить финал на случайных удаленных URL, которые исчезнут.
- Проверить файл через ffprobe; отдельно убедиться, что рендер действительно проигрывается и имеет видео и нужную аудиодорожку.

## Визуальные стили

**Рисованный карандаш** (опционально, если подходит смыслу): дизайн «на двойках» или приблизительно 12 уникальных рисунков/секунду; небольшое изменение контура между кадрами («кипение»), разрывы линий, штриховка вместо плоских заливок, фактура бумаги. Это прием автора исходного видео, **не обязательное требование** всех роликов. Финальный FPS выбирать под площадку/совместимость.

**Премиальная продуктовая графика:** спокойная кинетическая типографика, небольшая глубина, осмысленные переходы, интерфейс в центре внимания, анимации только там, где поясняют устройство сервиса.

**Обучающее видео:** визуальная метафора, схема/масштаб/причинно-следственные связи, подсвечивание важного; не создавать плотную стену текста.

## Брендинг ServGo и GRUNVALDLAB

Использовать подтвержденные официальные логотипы, графику и интерфейсы из исходных ресурсов владельца, при необходимости сверять актуальные материалы на servgo.ru. Не изобретать «похожий» логотип. Если бренд-ассеты пока недоступны, делать аккуратную временную текстовую заставку и явно обозначать, что логотип не подтвержден.

Для заявлений о функциях и ценах ServGo сверять текущий продукт/документацию, не брать устаревшие значения из памяти. Отличать реальные возможности от планируемых.

## Звук и монтаж

Голос — приоритет над музыкой; музыку приглушать под речь и делать плавные переходы. Субтитры должны быть точными по смыслу, вычитанными, в безопасной зоне кадра. Для интервью/обрезки речи использовать точные word-level метки и сохранять начала и окончания слов; финальную проверку делать по реальному аудио.

## Ограничения и этика

Фотореализм и сложное движение тел в кодовой анимации могут быть значительно труднее; гибрид с видеогенерацией допустим, но такие кадры помечать как синтетические при потенциальной неоднозначности. Не считать обещания о «сотнях роликов по одной подписке» доказанной себестоимостью: учитывать тариф, лимиты, стоимость рендера, правки и лицензии. Не передавать ключи в коммиты, не запускать GitHub Actions для рутинного рендера, когда есть SSH/локальные возможности.

## Обязательная проверка перед сдачей

- Есть четкое начало, цельная последовательность и полноценное окончание.
- Ни один титр не обрезан, в т.ч. на маленьком экране 9:16.
- Каждая сцена читается с первого просмотра, длительности соответствуют речи.
- Нет случайных фликеров, обрезанных слов, резких аудиосклеек и расхождения субтитров.
- Файлы сгенерированы и проверены, а не только названы в отчете.
- Источники чужих медиа и права использования перечислены в ASSETS.md.
- Список ошибок обновлен для будущих итераций.

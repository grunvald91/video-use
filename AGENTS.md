# AGENTS.md — обязательная политика экономного использования GitHub Actions

**Обязательно для всех ИИ-агентов и разработчиков** (Codex, Claude Code, Copilot и делегированных агентов) при работе в этом репозитории. Применяется к разработке, диагностике, тестам, CI и деплою.

**Главный принцип:** GitHub Actions — ограниченный платный ресурс. Один осмысленный запуск с проверяемым результатом лучше десятков попыток. Не трать минуты, если задачу можно безопасно выполнить иначе.

1. **Сначала без Actions.** Используй доступные локальные инструменты, GitHub API, локальные/серверные тесты и существующие средства деплоя. Actions — лишь при обоснованной необходимости.
2. **Без массовых запусков.** Не запускай пачки workflows параллельно и не создавай отдельный workflow для каждой мелкой операции. Объединяй взаимосвязанные проверки.
3. **Сначала анализ.** До запуска проверь существующие workflow, триггеры, предыдущие результаты, уже выполненные проверки и возможность повторного использования артефактов.
4. **Никаких слепых повторов.** После ошибки сначала прочитай логи, найди первопричину и внеси проверяемое исправление. Повтор без изменений запрещён.
5. **Устраняй дубли.** Где это применимо, используй `concurrency`, осмысленный `cancel-in-progress`, фильтры `branches` / `paths` / событий. Не отменяй опасным образом production-деплой.
6. **Ограничивай ресурсы.** Устанавливай `timeout-minutes`, кешируй зависимости и запускай узконаправленные тесты; полный прогон — при необходимости, особенно перед релизом.
7. **Контролируй бюджет.** Перед ресурсоёмкими операциями оцени число запусков, длительность и ожидаемый расход billable minutes (с учётом типа runner). При риске превышения оставшегося лимита — сначала запроси разрешение владельца. Не представляй оценку как факт.
8. **Не жертвуй безопасностью.** Обязательные проверки для production, секреты, права доступа, миграции и возможность отката должны оставаться защищёнными. Ускоряй проверки, а не отключай их ради экономии.
9. **Исправляй системно.** Найдя неэффективный workflow, предложи/внеси исправление его конфигурации, а не обходи проблему раз за разом.
10. **Отчитывайся.** После существенной работы сообщи количество фактически запущенных Actions, результаты и *подтверждённый* расход минут, если данные доступны. Отделяй факты от оценок и прямо отмечай недоступную телеметрию.

## Перед вызовом Actions — чек-лист

- Можно ли решить задачу через GitHub API, доступный терминал или сервер?
- Не выполнена ли уже нужная проверка? Что говорят логи предыдущего прогона?
- Какой один минимальный workflow нужен и сколько минут он может потратить?
- Не вызовет ли событие ненужные проверки или деплой? Есть ли `concurrency` и ограничения?
- Сохраняются ли обязательные проверки безопасности и ограничения production?
- Если лимита может не хватить — получено ли явное согласие владельца?

Для *исключительно документационных* коммитов можно использовать `[skip ci]`, только когда автоматические проверки не нужны и это не блокирует обязательные статусы PR. Для изменений кода и production запрещено применять `[skip ci]` как способ обхода требуемых проверок.

**Делегирование не снимает ответственности:** передавая задачу другому агенту, явно передай эту политику и требуй выполнения.

## Режиссура и видеогенерация GRUNVALDLAB

Для задач создания моушн-графики, кодовой анимации и объясняющих роликов сначала читать `skills/grunvald-code-animation/SKILL.md`, затем его файлы `references/STYLE_DNA.md` и `references/MISTAKES.md`. Для монтажа снятых исходников дополнительно читать корневой `SKILL.md` и использовать `helpers/`.

**Основная среда: Codex Cloud** или подходящее исполняемое окружение ChatGPT. **Не предлагать и не задействовать Codespaces по умолчанию** из-за ограниченных квот пользователя. Не использовать GitHub Actions для рендера. При необходимости дополнительной зависимости проверять наличие Node.js 22+, Chromium, FFmpeg и доступность npm до запуска полного производственного цикла. Финальный результат — проверенный MP4 и редактируемые исходники; не заменять ролик описанием монтажа.

У пользователя есть постоянное разрешение на самостоятельные творческие монтажные решения. Это не является разрешением на платные действия, публикацию, изменение production-систем или удаление исходных материалов.


## Автомонтаж видео «голова + экран»

При входном видео, где есть говорящая голова, запись экрана или оба источника, дополнительно читать `skills/golova-ekran/SKILL.md` и соответствующие `references/`. Применять скрипты `skills/golova-ekran/scripts/montage.py` только после проверки зависимостей, теста с фрагментом исходника и проверки безопасности. Сохранять целые слова, смысл, логичное вступление, чистые стыки и проверенный MP4. Не требовать отдельного утверждения каждого творческого решения, когда пользователь делегировал самостоятельный монтаж; сомнительные смысловые вырезы не производить без основания. Запрещено использовать маркировку `--skip-repeats` как способ выдать непроверенный мастер за готовый.

Источник и лицензия: `skills/golova-ekran/UPSTREAM.md`. Для этого импорта GitHub Actions не запускались; установка в репозиторий не равна установке программных зависимостей на машине или глобальной регистрации скилла в ChatGPT.
